# 実機比較検証の手順（Sleep as Android 原典 vs 自作判定）

> 📅 2026-10-25 作成（MLR r4 MiniMax/GLM critical指摘採用）・検証実施者: ふくけい（実寝）+CC（解析・比較）

## ⚠️ 事前固定（MLR r4採用・検証開始前に変更禁止）

### 指標（一致率は1つにしない・4指標を事前固定）

1. **1分epochの段階完全一致率**（両者とも判定可能なepochのみ分母）
2. **混淆行列**（原典段階 × 自作段階のクロス集計）
3. **境界2epoch除外の一致率**（段階遷移境界の影響を除外）
4. **DEEP/LIGHT比率の差**（一致率と別の合格線・割合差>10ポイントなら注意）

- UNKNOWN の扱い: 両者の一致率計算から除外し・別集計
- 原典がREM等の細分類を持つ場合: REM/浅眠の一致扱いはしない（不一致として計上し・ラベル意味論の乖離として切り分け報告）

### fail条件（事前固定）

| # | 条件 | 対応 |
|---|---|---|
| F1 | 原典CSVの**サンプリング間隔が1分でない**（タイムスタンプ差分で実測） | 検証中止・レートに合わせて再合成/再設計 |
| F2 | CSV列名・区切り・文字コードの解析に失敗 | 検証中止・形式解析タスク化 |
| F3 | 原典の段階ラベルが2値（DEEP/LIGHT）と非互換（4段階等） | ラベル意味論の乖離として切り分け・一致率は「深眠/非深眠」の2値で再計算 |
| F4 | 比較可能epochで完全一致率<50%（原典と自作がほぼ無関係な判定） | 検証中止・実装見直しタスク化 |

### 検収項目（原典CSV受領直後に実施・全項目を検収票に記録）

1. 実ファイル名と列名（1行目）
2. 行数と時間粒度（タイムスタンプ差分でサンプリング間隔を実測）
3. 区切り文字・文字コード
4. 日跨ぎ時刻の表現
5. 段階ラベルの列挙（何段階か・記号は何か）
6. actigraphy値の範囲（min/max/中央値/四分位）— 合成データ較正にも使用

## 手順

### Step 1: ふくけいの作業（実寝検証）

1. Google Play で **Sleep as Android** をインストール
2. 枕元（マットレス上）にスマホを置き・トラッキング開始して寝る
3. 朝・記録確認 → Export → CSV（`sleep-export.csv`）
4. CSVをこのセッションに渡す

### Step 2: CCの作業（検収→投入→比較）

1. **検収**: 上記6項目を実測・fail条件F1〜F3をチェック
2. **投入**: 振幅列を抽出 → `ActivityClassifier.update()` → `SleepPhaseDetector.update()`（validation/synthetic.ts と同じパイプライン）
3. **比較**: 事前固定の4指標を計算・fail条件F4を判定
4. **報告**: 一致率+混淆行列+乖離パターンの分析+「骨格一致/不一致」の結論

### 注意

- 原典スコアとの比較は **行わない**（9測定のうち5測定が自作側で未入力のため比較不能・段階判定系列のみ比較）
- score.json（合成データのもの）は synthetic-debug-only・比較対象外（ファイル内 purpose 明記済み）
- 判定等価性はこの比較実験で初めて実証される（静的解析上は未証明・MLR r4 OR1指摘のとおり）
